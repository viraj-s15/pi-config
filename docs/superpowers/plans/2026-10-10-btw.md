# `/btw` Implementation Plan

> **For agentic workers:** Implement in order using test-driven-development. The context, thread and command integration are closely coupled; use a separate reviewer after integration.

**Goal:** Add memory-only side questions with current conversation context and no fork action.

**Architecture:** Snapshot Pi's active projected messages, make a separate authenticated model-registry request with no tools, and render it in a temporary overlay. A bounded in-memory thread provides follow-up context without session writes.

**Tech Stack:** TypeScript, installed Pi 1.1 APIs, Pi TUI, Node test runner and jiti.

---

- [ ] Write failing tests importing the new modules through jiti. Use real Pi message conversion and transcript resolution; fake only the provider boundary.
